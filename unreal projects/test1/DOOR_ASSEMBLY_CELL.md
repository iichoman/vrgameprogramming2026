# 로봇 도어 장착 셀

작성일: 2026-10-10

## 목적과 구현 범위

`/Game/DigitalTwin/Maps/DoorAssemblyCell`은 `CamryAssemblyPreview`를 복제한 독립 작업 맵이다. 기존 차체·좌우 도어·왼쪽 6점 검사·지그 후보를 유지하며, 받은 로봇 메시를 네이티브 C++ Actor에 연결한다. 원본 맵과 로봇 Blueprint는 수정하지 않는다.

공정은 대기 → 집기 접근 → 잡기 → 들어올림 → 운반 → 차체 접근 → 센서 기반 정렬 → 선택적 독립 검증 → 가상 체결 → 해제 → 후퇴 → 완료·품질 판정 순서다. 목적은 공정 조건과 실제 계산 상태에 따른 장착 결과를 검토하는 기반을 만드는 것이다. PID 자체의 구현은 목표가 아니라 로봇 관절 동작을 계산하는 수단이다.

## 실행

새 맵을 열고 Play를 누른다. 화면 패널의 Start / Stop / Reset 또는 Enter / Space / R을 사용한다. 오른쪽 마우스 드래그와 휠로 카메라를 조작하며 Home은 카메라를 복원한다. 완료·정지·고장 이후에는 Reset 후 시작한다. Reset은 시뮬레이터를 초기 조건으로 복원하는 기능이며 실제 설비의 안전 복귀 경로가 아니다.

프로젝트의 시작 맵과 게임 기본 맵을 새 조립 셀로 설정했다. 패널의 TCP 오차는 현재 이동 단계의 목표까지의 오차이며, `Door mount`는 실제 문과 정상 장착 기준 사이의 위치·방향 오차다. Start는 대기 상태, Stop은 공정 진행 중에 활성화된다.

`DoorAssemblyCell` Actor에는 차체와 로봇 참조, 잡는 위치(TCPInDoorCm), 도어 대기 위치, 접근·들어올림·운반 경유점, 정렬 공차·안정 유지 시간·타임아웃이 있다. `RobotArm` Actor에는 관절별 영점 변환·회전축·가정한 회전/속도/가속도 제한과 PID 게인이 있다.

## 계산 흐름

도어 목표 자세 → 잡는 위치를 반영한 TCP 목표 → 전체 위치/방향 수치 IK → 관절 공간의 5차 목표 궤적 → PID 속도 명령 → 1차 모터 응답과 가속도 제한 → 현재 관절 각도 적분 → FK → 도어의 실제 자세 → 기존 검사.

- FK/IK 길이는 cm, 각도는 rad다. 화면과 설정은 명시한 cm/mm/degree를 사용한다.
- IK는 감쇠 최소제곱, 수치 Jacobian, 관절 제한과 반복 한도를 사용한다. 실패한 해는 관절 목표로 적용되지 않는다.
- 목표 궤적은 PID의 기준값이며 관절 메시를 직접 애니메이션하지 않는다. 현재 각도는 속도를 고정 시간 간격(초기 1/120s)으로 적분한 결과다. 렌더링 프레임과 제어 계산 간격을 분리한다.
- PID는 측정 각도·각속도를 사용하며 출력 포화와 적분 누적 제한이 있다. 모터 응답은 단순화한 교육용 모델이다. 실제 토크·중력·도어 하중 역학을 계산하지 않는다.
- 그리퍼는 잡는 순간의 TCP-도어 상대 자세를 보존한다. 문은 실제 TCP를 따라가며 장착 목표로 순간 이동하지 않는다.
- 장착은 TCP 추종 정착과 정렬 센서 기준으로 진행한다. Basic 모드는 정렬 센서만 사용하며, IndependentVerification 모드는 별도 측정 모델의 자세와 6점 검사도 확인한다. 두 모드는 동일한 집기·기준 좌표·구동 검사를 유지한다. 2mm/0.5도/0.3초는 교육용 설정이며 OEM 공차가 아니다.
- 가상 체결은 그 순간 달성한 도어 자세를 차체 기준으로 보존한다. 그리퍼를 해제해도 도어는 차체에 남는다. 탄성 회복·힌지 처짐·볼트 축력은 미구현이다.

## 로봇 데이터의 근거

`Scripts/robot_calibration.json`은 Unreal 5.8.3에서 로봇 BP를 실제 로드해 추출한 6축 피벗, 영점 quaternion, 17개 메시 연결, TCP_Estimate를 담는다. CTRL_Robot과 REST_Ai의 변환을 접어 네이티브 계층에 사용한다. 원본 BP의 양수 관절각은 -Z 방향이고, 새 네이티브 제어는 명시한 +Z축의 rad 각도를 사용한다.

정확한 KUKA 모델명, 제조사 관절 제한, 실제 그리퍼 접촉 TCP는 검증되지 않았다. 설정된 관절 범위·구동 응답·작업 배치는 교육용 가정이다. 지그는 기존의 접촉 후보 시각화로 유지되며 접촉 구속·반력·안착을 계산하지 않는다. 경유점 기반 경로에는 범용 충돌 회피가 없고, 전체 로봇/차체/지그 간섭 검증은 별도 작업이다.

## 기록과 검증

실행 CSV는 `Saved/DoorAssemblyRuns`에 저장한다. 시뮬레이션 시각, 공정 상태, 잡기/체결 상태, 실제·목표 TCP, 위치·방향 오차, 현재 관절 각도, 도어 장착 위치 오차를 기록한다. 소스·설정의 버전을 함께 보관해 실행 조건을 추적한다.

`Scripts/setup_door_assembly_cell.py`는 새 맵을 구성하고, `Scripts/verify_door_assembly_cell.py`는 동일한 네이티브 고정 시간 간격 계산으로 전체 공정·정지·복구·IK 실패와 프레임 조건에 따른 재현성을 확인한다. 기존 맵이 열린 다른 에디터와 동시에 같은 맵을 저장하지 않는다. 검증 결과는 `Saved/DoorAssemblyVerification.json`을 확인한다.

수학 검증은 Unreal Automation의 `test1.RobotControl` 테스트에서 FK, 전체 자세 IK, 실패/잘못된 입력과 관절 서보의 정착·속도·가속도 제한을 확인한다. 수학 검증, 공정 소프트웨어 검증, 화면 육안 확인, 실측 비교는 서로 다른 검증 수준이다. 실제 차량 정확도나 현업 적용성을 입증하려면 실측 자료·하중 모델·간섭 검증을 후속으로 연결해야 한다.

## 2026-10-10 검증 결과

- Unreal 5.8.3 Development Editor 네이티브 빌드 성공.
- `test1.RobotControl` Automation 3개(FK, IK, 관절 서보) 통과. 결과: `Saved/RobotControlAutomation/index.json`.
- 별도 UnrealEditor-Cmd 프로세스에서 원본과 저장된 새 맵을 다시 로드해 Actor 참조, 6관절, 17개 메시, TCP, 도어 기준 자세와 지그 보존을 확인했다. 두 맵의 파일 SHA-256은 검증 중 불변이었다.
- 저장된 설정 그대로 전체 공정을 60 FPS와 30 FPS 조건에서 완료했다. 두 조건 모두 계산 시간 14.6833초, 최종 문 위치 오차 1.25324mm, 방향 오차 0.00826도였다. 이 수치는 교육용 시뮬레이션 결과이며 실측 정밀도가 아니다.
- 운반 중 Stop의 자세 유지와 Reset, 도달 불가 목표의 IK 실패 및 무이동, 잘못된 시간 입력 거부를 확인했다. 고장 주입 후 픽업 설정은 정상 값으로 복원된다.
- 실제 PIE 화면에서 문 운반·장착·해제·로봇 후퇴까지 확인했다. 공정 검증 상세 결과: `Saved/DoorAssemblyColdLoadVerification.json`.

공정 CSV의 `position_error_mm`와 검증 보고서의 최대 추종 오차에는 단계 목표가 바뀐 순간의 남은 이동거리도 포함된다. 이를 최종 장착 오차로 해석하지 않는다. 최종 장착 정밀도는 문 기준의 위치·방향 오차로 확인한다.

## 2026-10-12 센서·품질·초기 배치 실험

Play 화면 상단 프리셋을 선택한 뒤 Start한다. 실행 중에는 프리셋 변경을 거부한다. 선택은 해당 조건으로 Reset하며, 이후 사용자가 문을 옮기면 Start는 옮긴 현재 자세를 읽고 정상 위치로 순간 이동시키지 않는다.

| 버튼 | 설정·기대 결과 |
|---|---|
| Normal | 편차 0, 독립 검증 사용, 정상 품질 합격 |
| Bias / Basic | 정렬 센서의 차체 Y 방향 +5mm 편차, 센서상 정렬 후 실제 불량 체결 |
| Bias / Verify | 같은 +5mm 편차, 독립 검증으로 체결 전 차단 |
| Displaced | 픽업 위치에서 (20,-30,10)mm 이동 및 yaw 2도, 현재 자세에서 집고 장착 |
| Too far | 문을 설정한 집기 복구 범위 밖으로 배치, 무이동 시작 거부 |
| Reversed | roll 180도, 그리퍼 자세 복구 범위 밖으로 시작 거부 |
| Missing | 도어 없음, 메시 숨김 및 시작 거부 |

센서는 실제 하드웨어나 이미지 인식이 아닌 가상 6자유도 자세 측정 모델이다. 차체 좌표에서 측정 위치에 일정 편차를 더하고 측정 회전에 편차를 적용한다. 정렬 제어는 측정 오차로 이전 명령을 보정하며 입력한 고장 편차를 직접 빼지 않는다. 독립 검증 센서는 별도의 편차·유효성 입력을 가지며 기본은 이상적 측정이다. 카메라 픽셀 해석, 지연·잡음·공통 원인 센서 고장 탐지는 아직 구현하지 않았다.

픽업 인식은 문 컴포넌트의 정확한 자세를 읽는 이상적 인식 가정이다. 접근·집기·들어올림 IK를 사전 검사하며 관절 상태·목표를 변경하지 않는다. 집기 순간 TCP 접촉 자세를 확인하므로 멀리 있는 문을 원격으로 붙잡지 않는다. 집기 중 문이 외부에서 이동하면 정지한다. 집기 복구 한도 500mm/30도는 제조사 값이 아닌 현재 그리퍼의 교육용 접근 조건이다. 충돌 검사·자동 우회는 아직 없으므로 접근 공간을 확보한 배치에서만 작업 가능성을 평가한다.

Details의 `Cell > Experiment`에서 Custom과 제어 모드를 선택하고 Placement/Sensors/Quality의 값을 설정한 뒤 Reset한다. Reset은 선택한 초기 배치·오류 조건을 재현하는 실험 초기화다. BeginPlay에서는 기본 Normal/Custom의 에디터 배치를 보존한다. 센서 편차와 배치 오류를 함께 적용할 수 있다.

기존 6점 검사기는 정상 대비 부호 있는 틈·단차 변화량을 계산한다. 공통 GapToleranceMm/FlushToleranceMm(초기 각각 ±2mm)을 모든 점에 적용한다. 점별 개별 상·하한과 수직 틈 검사 방향은 후속이다. 현재 원시 검사값은 센서 입력과 분리한 실험 평가값이고, 개선 제어의 차단은 독립 센서 측정 자세에서 계산한 검사값을 사용한다. 운반 중의 검사 불합격은 최종 불량 판정이 아니며 최종 Outcome은 Complete에서 확정한다. QualityFail은 공정 완료 후 품질 불합격, Blocked는 미완료·차단, Stopped는 사용자 정지다.

CSV에 정렬·독립 센서 오차, 6점 틈·단차·합격 여부, 최종 Outcome을 추가했다. 같은 RunID의 JSON에는 시나리오·모드·픽업 자세·편차·공차·PID 설정·실패 이유와 모델 가정을 저장한다. 기록은 `Saved/DoorAssemblyRuns`에 있다.

`Scripts/verify_cell_experiments.py`는 저장된 맵에서 정상 30/60 FPS, 기본·개선 센서 편차, 배치·편차 조합, 각도 편차, 집기 거부·IK 무이동, ±2mm 경계, 센서 무효, 수동 배치·정지·외부 이동, CSV/JSON 결과 일치와 기준·맵 파일 보존을 검증한다. 결과는 `Saved/DoorCellExperiments.json`이다. 실행 중 에디터에서는 `Scripts/run_cell_experiments_live.py`를 실행해 현재 레벨을 검증할 수 있으며, 스크립트는 맵을 저장하지 않는다.

검증 수치: 정상 14.6833초 및 최대 절대 단차 변화 0.7659mm; +5mm 센서 편차 Basic 15.2833초 및 최대 절대 단차 변화 5.1215mm(QualityFail); 동일 편차 독립 검증 12.6167초에 미체결 차단; 이동·회전된 문 14.6917초 및 최대 절대 단차 변화 0.8629mm(Pass). 모두 교육용 계산 결과다.
