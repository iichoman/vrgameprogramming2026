# factory_p1 — 공장 편집기와 휠 작업

수정일: 2026-10-27

`Content/DigitalTwin/Maps/factory_p1`을 열고 **Play**로 사용한다. 네이티브 C++ 편집기에서 공장과 설비 배치를 바꾸고 저장한 뒤, 연결된 KUKA 로봇으로 앞왼쪽 휠 한 개를 공급대에서 차량 허브까지 운반·정렬한다.

## 빠른 시작

1. `factory_p1`에서 Play한다.
2. 이전 A 저장 배치가 있으면 그것이 우선 열린다. 새 KUKA 예제를 보려면 왼쪽 패널 아래 **기본 배치로 복원**을 누른다. 저장 파일은 덮어쓰지 않으며 Undo로 복원할 수 있다.
3. **작업 실행**으로 공급점 접근 → 인수 → 상승 → 운반 → 허브 접근 → 정렬·검사를 확인한다.
4. 정지/완료 후 **편집 복귀**로 현재 배치의 시작 상태로 돌아온다.
5. 공급대나 로봇을 이동한 뒤 다시 실행해 도달 가능 여부, 이동 거리, 사이클 시간을 비교한다.

구역 이름은 기본으로 숨겼다. 왼쪽 **시점 → 구역 이름 표시**에서 켜고 끈다. 설비 이름과 공정 흐름도 별도로 표시할 수 있다. 변경한 보기 설정은 다음 실행에도 유지된다.

## UI와 조작

| 위치/입력 | 기능 |
|---|---|
| 왼쪽 | 실행·결과, 카메라·표시, 공장 크기, 선택 속성, 공정 순서, A/B 저장 |
| 하단 | 구역/설비 추가, 분류 탭, 격자 맞춤, 배치 취소 |
| 좌클릭·드래그 | 대상 선택·이동 |
| 휠클릭·드래그 | 카메라 평행 이동 |
| 우클릭·드래그 | 입체 시점 회전; 평면 시점은 기울기 고정 |
| 마우스 휠 | 확대/축소; 패널 위에서는 패널 스크롤 |
| WASD / 방향키 | 작업 화면에 포커스가 있을 때 보조 이동 |
| F | 선택 대상에 시점 맞춤 |
| Ctrl+Z | 실행 취소 |
| Ctrl+Y / Ctrl+Shift+Z | 다시 실행 |
| Esc | 진행 중 이동·크기 조절·추가 취소 |
| Delete | 선택 항목 삭제; Undo 가능 |

문자/숫자 입력 중에는 배경 카메라 단축키가 작동하지 않는다. 숫자는 Enter 또는 다른 입력칸으로 이동할 때 적용된다. 긴 왼쪽 패널과 좁은 하단 목록은 스크롤한다.

### 설비·구역 추가

하단에서 항목 선택 후 바닥을 클릭한다. 초록 테두리가 배치 후보 위치다. 구역은 시작점부터 끝점까지 드래그한다. 추가 후 왼쪽에서 한국어/영어 이름과 위치·방향을 조절한다. 구역은 작업/공급/대기/보행/재작업/확장 용도를 정한다.

차량 정지대, 휠 공급대, KUKA/직교 장치를 선택해 **휠 작업에 연결**하면 단일 휠 작업이 그 설비를 사용한다. 설비를 여러 개 추가해도 모두 자동 실행되지는 않는다. 새 로봇을 연결할 때 기존 로봇과 바닥 영역이 겹치지 않게 배치한다.

### 공장·구역 크기

- 공장: **공장 테두리 선택** → 노란 변/모서리를 드래그한다.
- 구역: 구역 선택 → 같은 방식으로 드래그한다. 회전 구역도 로컬 방향으로 조절한다.
- 반대편 경계는 고정한다. 공장 왼쪽을 늘리면 공장 원점이 바뀌며 내부 설비 좌표는 유지된다.
- 공장 크기는 길이 12~200m, 너비 12~120m. 구역은 각 변 0.2~200m.
- 공장 밖 항목은 빨간색으로 표시한다. 밖으로 나간 설비는 실행 조건에서 거부한다.
- 구역과 그 안의 설비를 묶어 이동하는 기능은 보류했다.

### 공정 흐름

기본 순서는 P01 차체 입고·준비 → P02 내장 → P03 하부 결합 → P04 휠 → P05 마무리 → P06 검사·출구다. 왼쪽 **공정 순서·동선**에서 선택 항목을 추가/제외하고 순서를 이동한다. 곡선 굽힘도 바꿀 수 있다.

곡선과 화살표는 명시적인 공정 순서를 표시한다. 구역이 이동/회전하면 연결도 따라간다. 차량 운반, 가동 중인 컨베이어, 최단 경로 또는 안전거리 계산 결과는 아니다. 공급·재작업 분기 동선과 다중 차량은 후속 개발이다.

## 현재 설비

| 설비 | 구현 |
|---|---|
| 차량 정지대 | 차량과 장착 기준 좌표 |
| 휠 공급대 | 로컬 휠 인수점 |
| KUKA 로봇 | 기존 링크 모델, 위치·자세 IK, 6축 관절 PID, 단순 그리퍼 |
| 직교 이송장치 | 이전 배치 호환·비교용 위치/방향 PID |
| 컨베이어 모형 | 도형 외형·점유 형상, 구동/운반 미구현 |

기본 KUKA 위치는 `(43.5,-3.3)m`, 공급대는 `(45.75,-3)m`, 차량 정지대는 `(42,0)m`이다. 세계 좌표로 고정된 동작을 재생하지 않으며 매번 현재 설비 기준에서 목표를 계산한다.

차량은 기존 ProcessModules의 차체 80개 메시와 앞왼쪽 휠 2개 메시를 참조한다. 원본 메시·표시 여부·허브 피벗을 보존한다. 다른 차량 시험 맵을 수정하지 않았다.

## 저장과 Undo

- A/B: `Saved/FactoryLayouts/layout_A.json`, `layout_B.json`. A는 일반 Play 시작 시 자동 로드한다.
- v2: 공장 원점·크기, 항목 ID/TypeId·이름·용도·위치·방향·크기, 작업 연결, 흐름 순서·굽힘.
- v1도 읽는다. 예전 직교 장치를 KUKA로 강제로 변환하지 않는다.
- 기존 저장을 덮어쓸 때 `.bak`를 남긴다. 잘못된 파일/지원하지 않는 설비는 현재 화면을 유지하며 로드를 거부한다.
- Undo는 최대 100건. 드래그 한 번은 기록 한 건이며 삭제한 ID와 작업 연결도 복원한다.
- 불러오기·기본 복원은 Undo 가능하다. 이미 쓴 JSON 파일 자체와 실행 중 관절 상태는 Undo 대상이 아니다.
- 이름/흐름 표시 설정: `Saved/FactoryEditorView.json`. 배치 기록과 분리한다.
- 팀 공유 기본 배치: `Scripts/factory_editor_default_v2.json`.
- Play 중 편집 내용은 `.umap`에 자동 저장되지 않는다. A/B 저장을 사용한다.

## 계산 범위

고정 스텝은 1/120초다. IK가 목표 관절각을 구하고 제한된 속도/가속도와 PID가 현재 관절을 갱신한다. 휠은 계산된 TCP 자세를 따라간다. 위치·방향·시간 제한을 만족해야 다음 공정으로 넘어간다.

시험용 기본 KUKA 사이클 약 23.38 시뮬레이션 초, 최종 좌표 오차 약 0.06mm를 확인했다. 현장 택트타임이나 실제 센서 정밀도를 뜻하지 않는다. 질량·중력·하중 토크가 포함된 구동기 모델이 아니라 이상적인 관절 가속도 모델이다.

간섭은 회전 바닥 영역과 휠 이동 구간의 단순 검사다. 활성 로봇·차량·공급대는 의도된 인수/장착 대상이라 장애물 검사에서 제외한다. 링크 전체의 충돌·자가 충돌·차량 정밀 접촉, 파지력·미끄러짐·토크·응력·진동·볼트 체결은 후속이다. 완료는 **허브 정렬 완료**이며 체결 품질 합격이 아니다.

공장 전체의 생산량·병목·인력/비용 비교는 아직 계산하지 않는다. 나머지 구역은 전체 공정 확장을 위한 배치 자리다. 구역 면적이나 로봇 수만으로 생산량이 늘어난 것으로 표시하지 않는다.
