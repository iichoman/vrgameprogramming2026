# 통합 차체 이송·타이어·문 조립 맵

`/Game/DigitalTwin/Maps/IntegratedAssemblyLine`을 열고 Play → Enter로 시작한다.
Space는 정지, R은 전체 초기화다. 우클릭으로 시점을 회전하고 휠로 확대·축소,
Home으로 전체 시점을 복원한다. 화면의 시작·정지·초기화 버튼도 사용할 수 있다.
화면의 시점 버튼 또는 `F1`~`F5`로 전체·첫 도킹 지점·왼쪽 타이어 로봇·
오른쪽 타이어 로봇·문 로봇 시점을 선택할 수 있다. 로봇 시점은 작업 지점을
따라간다. `WASD`는 수평 이동, `Q/E`는 높이 이동, `Shift`는 빠른 이동이다.
이동·회전·확대하면 자유 시점으로 전환된다. 키 입력 전 플레이 화면을 클릭한다.

공정은 차체 6m 반입 → 양측 로봇의 타이어 4개 장착 → 차체 10m 이송
→ 별도 로봇의 왼쪽 앞문 장착·검사 순서다. 첫 이송은 8초+도킹 1초,
두 번째 이송은 10초+도킹 1초다. 타이어와 문은 차체가 도착하기 전 공급 위치에
남아 있으며, 체결된 타이어는 다음 구역으로 이동하는 차체를 따라간다.
중간 정지 후에는 자동 재시작하지 않고 초기화한다. 앞 공정의 실패는 다음 공정을 차단한다.

`choi`의 42개 차량 모듈과 해당 메시를 그대로 재사용한다. 타이어의 목표 위치는
`process_vehicle_manifest.json`의 네 휠 중심을 차체 좌표로 변환한 값이며,
좌우 로봇의 IK와 후륜 이동 준비 자세를 이 위치에 맞춰 다시 계산했다.
기존 원통형 타이어와 단순 차체 메시 대신 분리 모델의 실제 표시 메시를 사용한다.
모듈의 자체 휠 이동 PID는 끄고 조립 셀의 관절 제어에 연결해 중복 제어를 피한다.

문 공정은 기존 문 셀의 **왼쪽 앞문 한 개** 범위다. 나머지 세 문과 다른 부품은
사전 장착 상태이며 모두 별도 모듈로 유지된다. 기존 문 기준 프레임과 검사점을
유지하면서 분리 모델의 왼쪽 앞문 메시를 해당 프레임에 연결한다.

이 맵은 기존 관절 제어·가상 센서·가상 체결을 연결한 교육용 공정이다.
실제 체결력, 파지력, 하중, 충돌 회피나 안전구역 검증은 추가 구현 대상이다.
이송 CAD의 레일은 두 작업 구역을 연결하도록 시각적으로 연장한 것으로,
원본 치수나 실차 운반 장치의 설계 적합성을 나타내지 않는다.

기존 `WheelAssemblyCell`, `DoorAssemblyCell`, `CAR_MODULE_TEST` 맵은 수정하지 않는다.
새 맵 생성은 `Scripts/setup_integrated_assembly.py`, 저장 후 재로드 검증은
`Scripts/verify_integrated_assembly.py`를 사용한다. 생성 스크립트는 기존 통합 맵을
덮어쓰지 않는다. 결과 파일은 `Saved/IntegratedAssemblySetup.json`,
`Saved/IntegratedAssemblyVerification.json`에 기록된다.

2026-10-21 검증: Development Editor 빌드 성공. 저장 후 새 프로세스에서
30/60 FPS 계산 모두 약 90.6초에 전체 공정 완료, 네 타이어와 왼쪽 앞문 합격.
타이어 최대 위치 오차는 약 1.84mm였다. 세 동작 단계의 정지·초기화,
타이어 센서 오류, 구역 간 이송 중 외부 이동, 문 센서 오류의 차단을 통과했다.
기존 타이어 이송/전체 시나리오와 문 셀 재로드 검증도 통과했다.
자동 검사는 NullRHI에서 수행했으며 화면 렌더링·시각적 간섭 검사는 포함하지 않는다.
