# 센서 기반 차체 반입 시연

언리얼에서 `/Game/DigitalTwin/Maps/SensorAssemblyLine`을 열고 Play를 누른다.
화면의 상황 버튼 또는 숫자 1~8로 상황을 고른 다음 `Enter`나 시작 버튼으로
실행한다. `Space`는 정지, `R`은 초기화다. 공정 중 정지·오류가 나면 초기화 후
다시 시작한다. 이 맵은 기존 통합 맵을 복제해 만든 별도 시연 맵이다.

화면의 `전체`, `도킹 센서`, `왼팔`, `오른팔`, `문 팔` 버튼 또는 `F1`~`F5`로
관찰 시점을 전환한다. `F2`는 도킹 센서 주변, `F3`~`F5`는 움직이는 로봇팔의
작업 지점을 따라간다. `WASD`로 수평 이동, `Q/E`로 높이 이동, `Shift`로 빠른
이동, 마우스 우클릭 드래그로 회전, 휠로 확대·축소한다. 이동·회전·확대 시
추적 시점에서 자유 시점으로 전환되며 `F1` 또는 `Home`으로 전체 시점을 복원한다.
키 입력 전에 플레이 화면을 한 번 클릭한다.

| 선택 | 현장에서 바뀌는 것 | 센서가 발견하는 것 | 제어 결과 |
| --- | --- | --- | --- |
| 1 정상 | 이송 장치가 차체를 이동 | 도착 스위치, 정지 속도, 도킹 위치 | 타이어 조립과 왼쪽 앞문 조립까지 진행 |
| 2 이송 멈춤 | 구동이 이동 중 정지 | 이동 명령 중 속도 0이 1.5초 지속 | 작업 차단, 정지 명령 |
| 3 도킹 위치 틀어짐 | 이송 목표가 옆으로 1cm 이동 | 도착은 감지하지만 위치 오차가 5mm 기준 초과 | 타이어 로봇 시작 금지 |
| 4 위치 센서 끊김 | 차체 위치 측정값 발행 중단 | 마지막 위치값이 0.25초 초과 | 작업 차단, 정지 명령 |
| 5 타이어 없음 | 왼쪽 앞 타이어 공급대에서 타이어 제거 | 부품 존재 신호 꺼짐 | 로봇 작업 중단, 양팔 정지 |
| 6 타이어 위치 틀어짐 | 왼쪽 앞 타이어를 공급 위치에서 4cm 이동 | 측정 위치가 계획 위치와 다름 | 왼팔의 접근 경로 재계산 후 조립 계속 |
| 7 파지 실패 | 왼팔 그리퍼가 타이어를 고정하지 못함 | 파지 확인 신호 꺼짐 | 한 번 재시도하고, 다시 실패하면 양팔 정지 |
| 8 타이어 위치 센서 끊김 | 왼팔 공급 위치값 발행 중단 | 마지막 위치값이 0.25초 초과 | 로봇 작업 중단, 양팔 정지 |

위 상황 선택은 설비 또는 센서 발행 동작만 바꾼다. 제어기는 상황 이름을 읽지 않고
점유·도착·차체 위치·속도의 측정값과 시각으로 판단한다. 도착 스위치는 순간 신호이며,
이후 차체가 멈출 때까지 위치와 속도 측정값으로 도킹을 확인한다. 도킹 조건이
0.5초 유지되어야 타이어 조립을 허용한다. 정상 이송 시 스위치 감지 후 관성에
해당하는 약 3.7mm의 추가 이동을 모델링하며 도킹 허용치는 5mm다.

도킹 후 **왼쪽 타이어 로봇**은 공급대 부품 존재·위치, 그리퍼 파지,
장착 위치의 가상 센서값으로 작업 단계를 결정한다. 타이어가 움직이면 새 위치를
읽어 접근 경로를 다시 계산한다. 파지 확인이 없으면 한 번 재시도한다.
측정값이 무효이거나 0.25초 넘게 갱신되지 않으면 동작을 중단한다.
화면에는 왼팔 상태와 센서 유효 여부·재시도 횟수가 나타나고, CSV에는
`left_robot_sensor_state`와 `ROBOT_DECISION` 이벤트가 기록된다.
오른쪽 타이어 로봇과 문 로봇의 독립 센서 판정은 아직 적용되지 않았다.

시작 전 작업 구역에 다른 `SensorWorkpiece` 태그의 Actor가 있으면 이송 명령을
거부한다. 이송·도킹 중 `Space`를 누르면 감속해 정지하고, 정지했다는 센서 확인
전에는 정지 완료로 기록하지 않는다. 오류 후 센서값이 다시 정상으로 돌아와도
자동으로 재시작하지 않는다.

화면에 도착·점유·측정 유효 여부, 차체 위치 오차와 속도가 표시된다.
플레이 중 도킹 지점의 청록색 상자는 가상 센서의 관찰 구역이며, 위쪽 표식은
도착 신호에 따라 색이 바뀐다. `LIVE/STALE`은 위치 측정의 갱신 상태이고
노란 표식은 센서가 보고한 차체 위치다. `F2` 시점과 이 표식은 센서 판단을
살펴보기 위한 시각화이며, 카메라 영상 자체를 분석해 측정하는 기능은 아니다.
`F3` 왼팔 시점에서는 작업 지점의 색 표식이 부품 존재·파지 확인 상태를 나타내고,
노란 구체가 측정된 타이어 위치를 보여준다. 빨강은 부품 없음, 노랑은 파지 전,
초록은 파지 확인이다.
매 실행의 측정과 판단 기록은 `Saved/SensorLineRuns/*.csv`에 남는다.
주요 이벤트는 `RUN_COMMAND`, `ARRIVAL_STOP_COMMAND`, `DOCK_ACCEPTED`,
`WHEEL_START_COMMAND`, `FAULT_STOP_COMMAND`, `STOP_CONFIRMED`이다.
`SAMPLE` 행에는 측정 위치·속도·유효 여부와 공정 상태가 담긴다.

`Scripts/verify_sensor_assembly.py`는 저장된 맵을 새 언리얼 프로세스에서 읽어
30/60 FPS 정상 공정 완료, 차체 이송 돌발상황 세 건과 왼팔 돌발상황 네 건,
작업 구역 점유, 운전자 정지 후 감속,
실제 월드에서 차체를 틀어 놓는 경우, 맵 파일 불변을 확인한다.
2026-10-27 검증 결과는 `Saved/SensorAssemblyVerification.json`에서 `success: true`다.
이 테스트는 NullRHI로 실행했으며 화면상의 배치와 시각적 간섭은 직접 확인해야 한다.

현재 센서 구조의 적용 범위는 첫 차체 반입과 도킹까지다. 도킹 후 타이어·문
조립 제어는 기존 관절 피드백과 조립 셀 검사를 사용한다. 후속 작업으로
안전구역 인원 감지, 부품 파지·관절 센서의 독립 측정과 반복 생산량 비교를
추가할 수 있다. 센서 측정은 시뮬레이션 내부 상태에서 만든 가상 값이며,
실제 설비에서 수집된 데이터로 보정한 모델은 아니다.
